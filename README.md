# Gensolid

**English** | [简体中文](README.zh-CN.md)

An open-source boundary-representation (B-rep) modelling kernel benchmarked against Parasolid. Most code is generated by LLM agents in a recursive self-improvement (RSI) loop; correctness is decided by a human-owned verifier.

> Status: **pre-alpha, M0 public development benchmark, 1088/1088 M1 development pairs and initial M2 modelling**. General surface intersection is still incomplete. See [the current evidence and limits](docs/m0-m1-status.md). The API will change; do not use in production.

## Rust migration of SMLib core paths

A built-in `RustGeometryBackend` handles supported curve/surface construction without C++. The third migration round adds independently certified rational oblique cuts through explicit `SheetCutOptions`, and extends cylindrical offsets to continuous multi-span patches. These join the existing fixed-orientation spatial sweeps and rational extrusion–plane intersections in checked `Session` modelling operations. See [current scope, examples and validation](docs/rust-migration-round3.md), the [second round](docs/rust-migration-round2.md), and the [first round](docs/rust-migration.md). General moving-frame sweeps, arbitrary freeform offsets and general surface intersections remain outside this scope; the optional SMLib facade remains available.

## Design highlights

- **Rust kernel**: the compiler is the first free verifier for LLM-generated code; kernel crates forbid `unsafe`, `unwrap`, and `panic`.
- **PK-style C interface**: integer tags, `GS_<CLASS>_<verb>` naming, option structs with an `o_t_version` field; the Python and WASM bindings share the same semantic layer (`gensolid-api`).
- **Parasolid data model from day one**:
  - analytic surfaces, NURBS, and procedural surfaces coexist; supported XT imports preserve their geometry;
  - topology of body / region / shell / face / loop / fin / edge / vertex, with non-manifold support;
  - per-edge and per-vertex local tolerances (tolerant modelling);
  - topological decisions go through exact predicates and interval arithmetic.
- **XT read/write is a first-class feature.**
- **Verifier first**: the validity checker, policy tests, and differential-testing framework exist before the modelling algorithms; agents are not allowed to modify them.

## What works today

| Crate | Contents |
|---|---|
| `gensolid-core` | Typed ID arena with generations, error codes, session precision and local tolerances |
| `gensolid-math` | Points/vectors/frames, outward-rounded interval arithmetic, exact `orient2d` / `orient3d` |
| `gensolid-geom` | Analytic/NURBS evaluation and derivatives, projections, supported analytic intersections, degree-one/two/three rational curve/plane and bilinear surface/plane intersections |
| `gensolid-topo` | Non-manifold topology, convex polyhedra, polygon extrusions, linear sweeps, homothetic lofts and line-edge splitting |
| `gensolid-modeling` | Checked modelling entry points; planar B-rep volume, area, centroid and inertia, including holes and cavities |
| `gensolid-mesh` | Output-only planar tessellation and analytic parameter patches with bounded chord deviation |
| `gensolid-check` | Validity checks (topological consistency, loop closure, manifold edges, points lying on curves/surfaces within tolerance) |
| `gensolid-xt` | Schema-aware text/neutral-binary import and validity reports; three real ABC text parts supported through their exact embedded schema; unsupported schema/geometry reported explicitly |
| `gensolid-step` | Part21 manifold-solid import with analytic/NURBS geometry, certified convex planar voids and body checks; planar AP203 writing |
| `gensolid-cli` | JSON file diagnostics, public development benchmark, OCCT comparison coverage, paired ABC import evidence and aggregate-only private score interface |
| `gensolid-api` | PK-style session and tag API |
| `gensolid-ffi` | C ABI and header `crates/gensolid-ffi/include/gensolid.h` |
| `bindings/python`, `bindings/wasm` | Python (PyO3) and WebAssembly bindings |
| `verifier/policy` | Repository policy tests (no literal tolerances, B-rep must not depend on mesh, `unsafe` only in FFI, etc.) |
| `verifier/oracle` | Public block corpus compared with OCCT out of process, when pythonocc is installed |

## Installation

Version **0.1.0** is available from [PyPI](https://pypi.org/project/gensolid/) and [npm](https://www.npmjs.com/package/gensolid).

Python (Python 3.9+, macOS 11+ on Apple Silicon):

```sh
pip install gensolid==0.1.0
```

The initial PyPI release provides a macOS ARM64 wheel; Windows and Linux wheels are not yet available.

JavaScript / WebAssembly:

```sh
npm install gensolid@0.1.0
```

Node.js:

```js
const { Session } = require("gensolid");
const session = new Session();
const body = session.bodyCreateSolidBlock(1, 2, 3);
console.log(session.bodyAskVolume(body)); // 6
console.log(session.bodyCheck(body)); // 0 faults
session.free();
```

For browsers, import `init` and `Session` from `gensolid/web` and call `await init()` before creating a session. Configure your bundler or server to serve `gensolid/web/gensolid_bg.wasm` alongside the generated JavaScript module.

Both initial packages expose block creation, topology queries, volume, bounding boxes, vertex coordinates, and body validation. They do not expose every Rust API described below or include the optional SMLib backend. No Rust toolchain is needed to install these binary packages.

## Building from source

Requires Rust 1.88+.

```sh
cargo test                                   # kernel + policy tests
cargo clippy --workspace --all-targets -- -D warnings
cargo build -p gensolid-wasm --target wasm32-unknown-unknown --release
pip install maturin && maturin develop -m bindings/python/Cargo.toml
```

Python:

```python
import gensolid
s = gensolid.Session()
body = s.body_create_solid_block(1.0, 2.0, 3.0)
assert len(s.body_ask_faces(body)) == 6 and s.body_check(body) == []
assert s.body_ask_volume(body) == 6.0
```

C: see `crates/gensolid-ffi/examples/block.c`.

Public development benchmark:

```sh
python tools/fetch-abc-smoke.py
cargo run -p gensolid-cli -- check corpus/abc-smoke
cargo run -p gensolid-cli -- benchmark --output target/m0-m1-m2-report.json
```

The ABC sample is one published model, not a representative corpus. The default benchmark also includes original OCCT solids and negative inputs; frozen manifests keep missing or modified files visible. The report keeps unsupported cases in the intersection denominator and separates OCCT agreement from comparison coverage. `benchmark` exits successfully when it writes a report with intact inputs; inspect its scores to assess coverage. The reserved `--private-score <receipt.json>` interface accepts only `suite_id`, `total`, and `passed`, so private cases can stay with an independent scoring service.

## Interactive geometry viewer

Run `python tools/viewer.py` and open `http://127.0.0.1:8765`. The local viewer calls the Rust kernel for revolution, multi-section solid lofts, smooth NURBS surface lofts and NURBS intersections. Rotate/zoom, change parameters, inspect checker results and export scene JSON. No frontend packages or external services are required.

New checked operations support convex off-axis revolution and corresponding convex polygon sections. Smooth lofts interpolate compatible rational curves. Arbitrary-degree NURBS curve/surface intersection provides interval root certificates; general surface/surface intersection provides numerical curves and a global possible-root cover, **without certified branch connectivity**. Preview meshes carry no chord-error guarantee. See [implementation scope and evidence](docs/advanced-modeling.md); run `python tools/benchmark-advanced.py` for the additional public probes.

The [surface modelling pipeline](docs/modeling-pipeline.md) adds checked graph sheets, directional curved prisms, restricted face splits with shared-edge/UV updates, convex planar sewing and Booleans, and planar offsets and shelling. These Rust APIs do not yet form a general curved-solid Boolean/offset pipeline.

## Roadmap

| Milestone | Theme | Acceptance metric |
|---|---|---|
| M0 | Verification infrastructure: checkers, XT/STEP reading, OCCT differential testing, benchmark suite, private test set | Validity report on real XT files |
| M1 | Geometry core: intersections, projection, full exact-predicate coverage | Surface-intersection branch coverage |
| M2 | Topology and basic modelling: Euler operators, extrude/revolve/sweep/loft, mass properties, tessellation | Mass-property error |
| M3 | Boolean operations (analytic surfaces → NURBS → tolerant → non-manifold) | Boolean success rate on randomly rotated model pairs |
| M4 | Fillets, chamfers, shelling, offsets, direct modelling | Fillet-chain success rate |
| M5 | XT writing, STEP AP242, sewing and healing | XT round-trip opens in Parasolid-based applications |
| M6 | Convergent modelling (mesh bodies), PK-style API coverage | Coverage against the Parasolid feature list |

Design decisions are recorded in [`docs/adr/`](docs/adr/); rules for agent development are in [`AGENTS.md`](AGENTS.md).

## Acknowledgements & licence

Gensolid stands on the shoulders of the following projects and literature.

### Core references

#### Open CASCADE Technology (OCCT)

<https://github.com/Open-Cascade-SAS/OCCT> · LGPL-2.1 with the Open CASCADE exception

Gensolid's primary open-source reference. We study OCCT's architecture, algorithm design, and documentation, and use it as a differential-testing oracle (run as a separate process by the verifier, comparing results on the same inputs).

Because OCCT is LGPL while Gensolid is Apache-2.0, Gensolid's source **contains no** code translated or adapted from OCCT, and does not link against OCCT. Algorithms are implemented independently from public literature and from OCCT's documentation and black-box behaviour. The rules are recorded in [`docs/adr/0007-references-and-provenance.md`](docs/adr/0007-references-and-provenance.md).

#### truck

<https://github.com/ricosjp/truck> · Apache-2.0 · RICOS Co. Ltd. and the truck contributors

A Rust B-rep kernel, and the reference for Gensolid's NURBS implementation. truck's licence is compatible with Gensolid's; any code ported from truck notes the source repository and commit in its file header and retains the copyright notice in [`NOTICE`](NOTICE).
