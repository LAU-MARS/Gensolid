# ADR 0006：验证器优先的 RSI 开发流程

状态：已采纳（2026-10-12）

## 背景

公开资料中所有可信的递归自我改进成果，都有一把系统自己控制不了的“尺子”。一旦系统能修改评分标准，它就会学会“看起来变好了”。CAD 内核还有一个特有的陷阱：先网格化再计算，测试也能通过。

## 决定

四层结构，只有 L0 由人类掌控：

| 层 | 内容 | 所有者 |
|---|---|---|
| L0 验证器 | `gensolid-check`、`verifier/` 策略测试、公开语料、私有保留测试集、OCCT 对拍、性能基准 | 人类（CODEOWNERS） |
| L1 实现 | 编码代理按规格实现功能、修复失败用例 | 代理 |
| L2 算法进化 | 针对求交、圆角、网格化等单个难算法做种群进化（OpenEvolve 式） | 进化搜索 |
| L3 元改进 | 改写代理的提示词、技能库、错误模式库；只有私有分数提升才采纳 | 外层代理 |

另有对抗用例生成：专门寻找让当前内核失败的输入，经人工抽检后进入私有集。

防作弊规则：

- 私有测试集不进入仓库（`verifier/private/` 在 `.gitignore` 中），代理只能看到分数。
- 候选方案超过当前冠军后，换随机种子再评一次，才正式采纳。
- 生成模型与评审模型使用不同模型。
- 机械可查的规则写进 `verifier/policy`，例如禁止字面量容差、禁止 B-rep 依赖网格。

## 后果

- M0 阶段先建验证器，再写建模算法。
- 每个阶段的验收指标（见 README 路线图）就是 L0 私有基准中的分数。
